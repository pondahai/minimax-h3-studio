## 流程（定案版）

### 1. 取材
- 從來源頁抓分格原圖（本例 `https://shezi.org.tw/assets/images/panels/butterfly-2026/panel-0X.png`），先完整讀一遍劇情、角色、台詞
- 漫畫版權屬原作者，原圖不放進 repo

### 2. 分鏡（人工）→ `storyboard.md`
- 單段 ≤ 12 秒；一個連續動作超過 12 秒就拆段，用「前段末幀 → 後段首幀」續接（標 ⟶續）
- 每段寫成秒級時間軸表：秒數區間｜畫面動作｜鏡頭｜聲音（台詞）
- 續接段的前一段最後一秒要寫明末幀構圖
- 台詞以中文約 4 字／秒估算，排進對應時段；童聲語速較慢，要多留空間
- 先定角色外觀表，全片一致；同系列沿用前一篇的角色外觀與參考音（`ref_<角色>.wav`），只有新角色才做候選
- 原漫畫若有科學錯誤要在分鏡稿註明並改正（例：《密度》第 4 格石頭標「密度比水小」，應為比水大）
- **畫面不要出現任何文字**（招牌、圖示標籤、標語）：H3 會畫成亂碼。標語改用字幕呈現
- **續接只用在同一景別、動作連續的段落**：續接段的首幀就是前段末幀，H3 只會延續那格畫面，不會從 prompt 補出場景。前段末幀要交代得出下一段的場景，不要停在特寫上
- **續接段要從特寫拉遠到角色時，加 Qwen-Image 尾幀（首尾幀）**，否則 H3 會自己畫角色、外觀走樣（《密度》S10 小明小美變大）；見下方「尾幀」
- **景別大幅切換（特寫↔全景）就開新段**，用 Qwen-Image 做自己的首幀，剪接上是一個「切」。反例：《密度》S07 停在軟木塞入水特寫，S08 續接後大水槽變成小杯子
- **時段不能太滿也不能太空**：約每 3–5 秒一個主要事件
  - 太滿，H3 會跳過：《密度》S08 4 秒內三樣東西依序沉底，結果一樣都沒拍到 → 改成「同時放手、一起下沉」一個事件
  - 太空，H3 會自己加戲（亂移鏡頭、換場景）：《密度》S01 3–7 秒只寫掂量海綿，鏡頭自己往下帶到空桌、切掉人物的頭（推測）
- 每個時段都要有看得見的變化（角色動作、道具變化或鏡頭運動）；安靜時段寫具體小動作（陽光閃爍、阿柴搖尾、鏡頭慢推），不要只寫「固定」
- 時間軸寫成因果順序（放手→下沉→觸底→驚訝），讓每一秒都有東西可畫
- **每一列都要有動作，包括第一列**：《彩虹》S05 第一列只寫「小明站著望向彩虹」，8002 就寫成 "his posture still"，被檢查程式抓到
- **寫明畫面裡有誰**：角色少於該格原圖時，在分鏡列裡寫「（畫面只有小明）」「（畫面沒有人物）」，否則 8002 會照圖把其他角色加進來
- **說台詞的時段寫成口型＋肢體動作**：配音用 TTS（各段音色一致），畫面讓說話的角色嘴巴開合、配手勢表情，大致對上 TTS 台詞的時段；旁白時段角色不開口（2026-10-29 起，《密度》S08 開始套用）

#### 試驗：8002 直接寫分鏡（`python draft_storyboard.py <篇目>` → `storyboard_8002.md`）
目標是讓 8002 逐步接手人工分鏡、人只在旁檢查。《彩虹》第一次試（2026-10-29，7 格一次送、規則摘自本節，約 22 秒）：**格式正確，內容還不能用**
- 每段都標續接（7 段全部 ⟶續），景別、場景整個換掉也標，違反續接規則
- 把只在第 7 格出現的林博士塞進 S02–S07，還編了漫畫沒有的情節（阿柴舔水珠、叼來瀑布照片、用透鏡模擬完整彩虹）
- 台詞過密：S01 4 秒塞 25 字；第 4 格的科學重點（下半部被地平線擋住）沒講出來
- 每段最後一列都空著（—）；沒寫「畫面只有某某」；沒有加「不要直視太陽」的安全提醒
- 做對的：阿柴的台詞有改給別人；文字標籤、說明框都改成口述或實景
- 判斷：目前仍由人寫分鏡

**分鏡檢查程式** `python check_storyboard.py <篇目> [分鏡檔]`（人寫的、8002 寫的都要跑）：段長 ≤12 秒、時間軸首尾相接、每列 2–6 秒、台詞語速（童聲 3.5、其他 4 字／秒）、每列有動作、阿柴不說話、說話者是已知角色、畫面不放字（文字、標示、箭頭、虛線、示意圖、筆記、「」…）、續接段要同一格且前段寫了末幀、和前一段重複、原圖沒有的角色、角色比原圖少時有沒有寫「畫面只有…」。
- 原圖每格有誰寫在 config 的 `panel_cast`（人看圖填，以後可試讓 8002 填）
- 人寫的《彩虹》分鏡也被抓出 S06、S08、S10 台詞太密、S07 一列 7 秒；S04、S08、S10 加了原圖沒有的角色是刻意的（警告，確認後保留）

**逐格送（第二、三次試）**：`draft_storyboard.py` 改成一次一格，附該格角色與前面段落標題；每格寫完跑檢查程式，沒過就把問題清單回饋給 8002 重寫，最多 2 輪，仍沒過的列在檔尾「未解決」。每輪原始輸出存 `storyboard_8002_rounds.md`
- 逐格後不再亂加林博士、每段都標格數，明顯比整篇送好
- 第二次（提示寫「1–2 段」）：每格都拆兩段續接、加戲湊長度，14 段 168 秒 → 提示改成「預設一格一段，唸不完才拆」
- 第三次：10 段 120 秒，和人寫的一樣長；S01、S07、S08 可直接用。仍有問題：S04 整段照抄 S03（已加重複檢查）、S06 重述 S05、S02 擬人化太陽、S07 用玻璃杯且沒有「不要直視太陽」、S10 林博士拿寫著字的筆記本
- 回饋常常沒用：時間軸寫成 0–4、5–8、9–12，回饋兩輪原封不動，要在 system prompt 直接舉正反例才改；「畫面有字」類問題回饋後也很少修好
- 檢查程式抓不到的：科學是否正確、安全提醒、玻璃杯、加戲、台詞是不是圖上原文。這些仍要人看
- 判斷：8002 已能出可用的初稿（約 1.5 分鐘），人改初稿比從頭寫快；分鏡改為「8002 逐格初稿 → 檢查程式 → 人工修」還差安全與科學把關，下一篇再試

**《聲音》（2026-10-30，第四次，`sound/storyboard_8002_review.md`）**：同一支腳本，10 段 120 秒；人只審科學、安全、加戲
- 檢查程式重寫 2 輪後仍有 25 項沒過，**多數是回饋了也沒改**（「畫面有字」、黑板寫字、`「` 引號、動作太少），和《彩虹》觀察一致
- 科學：照抄原作有瑕疵的比喻（傳球）還畫成球飛過空中，和「空氣不會跑遠」矛盾；一格有三個情境時擠成一段、漏掉主旨（固體最快…）；說話者和聽者顛倒 → **原作比喻要人先判斷對錯，8002 不會質疑原圖**
- 安全：規則 10 寫了仍沒加「打孔請大人協助」，因為它乾脆跳過打孔步驟 → 安全提醒要明列在該格的提示裡，不能只靠通則
- 加戲：路人角色換成主角、阿柴說「汪」、結尾自編角色入場；「預設一格一段」讓資訊多的格（第 4 格三情境）被壓縮
- 能接手：分格對應、段落結構、從圖抓台詞原文、段數控制。不能接手：科學判斷、比喻改寫、安全提醒、續接判斷、畫面不放字
- 判斷：仍是「8002 初稿 → 人工修」，人工修改量比《彩虹》第三次大；下一步可試在 `draft_storyboard.py` 加每格的人工備註（科學更正、安全句、該格段數）一起送

### 3. 擴寫（8002）→ `python expand.py <篇目>` → `prompts/SXX.txt`
- 風格、角色外觀、不放字規則寫在 `config.json`（`style`、`characters`、`no_text_rule`），system prompt 其餘部分全篇共用
- **`style`／`style_en` 只寫畫風、色調、光線，不寫場景道具**：《彩虹》把「戶外木桌」寫進 `style_en`，8002 就把木桌塞進微距水滴、山坡、草地噴水等每一段。場景寫在各段分鏡裡（《密度》每段都在木桌旁，所以當時沒出事）
- **8002 收到的是「人工分鏡文字＋整格原圖」**，不會自己切圖，也不是看圖編劇情：分鏡由人讀過原圖後手寫，圖只供參考外觀與畫風
- 網站原圖本來就是一格一張（`panel-01`…`panel-07`），一格對應一段時直接送原圖，不用切
- **一格拆成兩段以上時，再把那一格切成各段對應的部分**（`panel-0Xa.png`、`panel-0Xb.png`，放在 `panel_dir`，不進 repo），`config.json` 的 `panels` 指向切好的檔名；只送整格會讓 8002 把屬於另一段的角色、道具畫進來（《彩虹》S09 只演第 6 格後半，卻照整格加了小美和阿柴）。切完要看一次，確定沒帶到相鄰區塊的角色
- 每段送「分鏡表＋對應漫畫分格圖」；system prompt 規定：
  - 逐條保留時間區段，不得合併、刪改、重排
  - 圖片只參考外觀、配色、畫風；忽略圖中文字；不准加分鏡表沒有的角色或情節
  - 有角色台詞的時段寫口型（嘴巴開合像在說話）＋表情手勢，旁白時段角色不開口；不寫台詞內容、驚呼、喊叫；結尾加「音訊：無對白、無人聲，只有自然環境音與輕快的兒童配樂」（原生音軌合成時整條靜音）。《蝴蝶》與《密度》S08 以外各段是舊規則（不寫任何發聲動作）擴寫的
  - 每個時段至少一個看得見的變化，不要讓畫面靜止
- **擴寫後必查**（8002 會自由發揮）：`python check_prompts.py <篇目> [段...]` 自動做 1–5，6 人工看
  1. 時間軸和分鏡一致
  2. 有沒有多出來的角色（看圖版特別容易照圖把角色塞進特寫；整行角色外觀清單也會被抓出來，要刪掉沒出場的）
  3. 「」引號裡的畫面文字
  4. 動作密度：時段描述太短（少於 15 字）、或寫了「固定／停留」卻沒有動作
  5. 有角色台詞的時段有沒有寫口型
  6. 前後段外觀是否連續（例如毛毛蟲顏色、蛹的顏色）
  7. 人工看道具有沒有被換掉（《彩虹》分鏡寫塑膠杯，8002 寫成 glass；程式抓不到）
- 有問題直接人工改 prompt 檔
- 路人角色要寫外觀（《聲音》S04 分鏡寫「路人小朋友」，8002 寫成 "faceless children"）；道具名稱要對（紅色大鼓被寫成 snare drum）

### 4. 配音（TTS）→ `python tts.py <篇目>`
1. 啟動 TTS：`cd ~/dgx-voxcpm-eval && source .venv/bin/activate && nohup python chinese_tts_server.py &`
2. **角色聲音人工挑選**：每個角色用不同的音色描述生成 3–4 個候選，給使用者挑完才繼續（不能自動選定）。使用者偏好台灣口音：描述裡寫「台灣華語口音」「台灣國語腔調」等（《密度》林博士選「六十多歲的台灣男教授，標準台灣華語口音，沉穩親切，語速慢」）
   - 台灣腔的參考音，ASR 容易聽錯（質量→資料），要人工試聽判斷，不能只看 ASR
3. 選定的音檔存成 `audio/ref_<角色>.wav`
4. 每句台詞用參考音克隆。**用 prompt 模式**（`clone_mode=prompt`＋`prompt_text`＝參考音的逐字稿）；reference 模式在短句、並列詞上容易唸出非中文
5. **ASR 核對**：`python asr_check.py <篇目>` 逐句轉寫，和原文比對。壞句每句重配 3 個版本，ASR 篩過後給使用者挑
6. 判讀 ASR：
   - **漏字也算壞句**：S05「長大後，牠找到…」ASR 只轉出「他找到…」，前三個字其實唸成了日文，第一次核對時被當成 ASR 誤差放過
   - ASR 會認錯同音字（卵→段落、蛹→勇），這種代表發音正確；轉成不同音的字（蛹→有）才是可疑
   - 最後一律以人工試聽為準
7. **送 TTS 前一律轉簡體**（`config.json` 的 `t2s: true`，`tts.py` 用 OpenCC t2s；《蝴蝶》為 false 以保留當時做法）：VoxCPM2 對繁體字常唸錯，例如《密度》S08「硬幣、湯匙」繁體送三次都唸成怪音，換同音字、改說法也沒用，轉簡體「汤匙」一次就對。原稿、字幕、`lines.json` 保留繁體
8. **多音字唸錯**（例：「變乾」的乾唸成乾坤的 qián）：VoxCPM2 不支援拼音標註，只能在送給 TTS 的文字裡換成同音、沒有歧義的字（乾→甘），字幕和 `lines.json` 保留正確的字；或改說法（變乾→乾燥）
9. 台詞錯字（例：「一隻小小的卵」→「一顆」）要同步改 `storyboard.md`、`lines.json`，再重配那句
10. 關閉 TTS 再進下一步

### 5. 首幀（Qwen-Image）→ `python qwen_frame.py <篇目> <名稱> 3 <參考圖...>`
- 《蝴蝶》只在需要重做的段落用（S10）；《密度》起改為**所有獨立段都先做首幀**：道具、圖解多的漫畫用 t2va 容易亂，也順便解決獨立段畫風不一致
- 續接段仍用前段末幀；首幀構圖要和該段 0 秒的分鏡一致（例：分鏡寫「走進畫面」，首幀卻已站好，就改分鏡與 prompt）
- **角色參考圖會被整張照抄**：《彩虹》用《密度》S01 首幀（小明舉海綿和石頭）當角色參考，6 段裡有 5 段的 seed2 原樣畫出海綿和石頭，S10 用《密度》S11 當參考，seed2 也照抄木桌和道具。挑 seed 時先排除照抄的；角色參考最好用道具少、只有角色的畫面（可以先做一張角色立繪）
- **角色立繪**（《聲音》起）：先做 `frame_prompts/chars.txt`（純色草地背景、全員並排全身、手上沒道具）→ `frames/chars.png`，之後各段的角色參考都用它。用前一篇的場景首幀當參考做立繪時，3 個 seed 有 1 個整張照抄原場景（《彩虹》S01 的彩虹天空），另 2 個是乾淨立繪但畫風較扁平；挑有完整服裝細節（林博士綠領帶）的那張
  - 立繪本身也會被照抄：12 段裡有 6 段至少一個 seed 把整排立繪角色貼進來（純色背景、多出林博士、兩隻阿柴）。**只有路人、沒有系列角色的段落（《聲音》S04）不要給立繪**，只給原圖，並寫明「沒有戴帽子、沒有背包、沒有狗、沒有老人」
- 挑 seed 時特別看時間軸衝突：動作的結果不能已經在首幀出現（木塊已浮在水裡、油層已倒好）
- 每段一個 prompt：`frame_prompts/<名稱>.txt`，輸出 `frames/<名稱>_seedN.png`；參考圖＝原漫畫分格＋前一篇影片抽出的角色畫面
- 參考圖：原漫畫分格＋影片中已生成的角色畫面（讓畫風和角色對齊影片）
- 直接輸出 16:9（1344×768），negative prompt 排除文字；生成 3 個 seed 給使用者挑
- 開 `qwen-image-comfyui` → 生成 → 關閉

### 5.5 分鏡審查（使用者）→ `python review.py <篇目>` → `review.html`
- 建議 seed 與理由寫在 `review.json`；首幀完成後產出審查頁：每段首幀候選（標建議 seed 與理由）＋時間軸、鏡頭、台詞；續接段註明接前段末幀
- 使用者審查、選定首幀後才開始跑 H3

### 6. 影片生成（H3）→ `bash run_series.sh <篇目>`／`bash run_jobs.sh <篇目> ...`
- 草稿等級：672×384、Turbo 8 步、INT8；每段 12 秒約 5.5 分鐘（含載入），段間冷卻 60 秒
- 獨立段用 t2va（`H3_T2VA=1`）；續接段用 ffmpeg 取前段末幀當 `H3_INPUT_IMAGE`
- 段落表在 `config.json` 的 `shots`：`[段, 秒數, 首幀來源]`，首幀來源 `-`＝t2va、圖檔路徑（如 `frames/S01.png`，選定的 seed 複製改名）＝用該圖、段名＝續接該段末幀
- 從 Windows 傳到 Spark 的 `.sh` 要先轉成 LF 換行，否則 bash 會報 `$'
'` 指令找不到；`comic-video/.gitattributes` 已固定 `.sh` 為 LF，啟動前仍先 `bash -n` 檢查語法
- Spark 上的目錄比照 repo：`~/h3-bench/comic-video/`（共用腳本＋`bench.py`）、`~/h3-bench/comic-video/<篇目>/`。《密度》已搬到新位置（第一批 11 段是重整前用舊腳本跑的）；《蝴蝶》還在 `~/h3-bench/butterfly/`
- 重跑某段：把舊檔移到 `out/archive/<段>_v1.mp4`、`run/<段>_v1/`，更新 prompt／首幀／`config.json` 後 `bash run_series.sh <篇目> <段>`（其他已存在的段會跳過）
- `run_series.sh`：整批依序跑，已有的段會跳過；失敗就停
- 在 Spark 上排隊等前一批跑完：`pgrep -f`／`pkill -f` 會比對到自己所在的 `bash -c` 或 ssh 指令（字串裡就有那個關鍵字），等待迴圈永遠不結束、或把自己的 ssh 砍掉。關鍵字寫成 `"[r]un_series.sh rainbow"` 這種形式避開；本機監看用 `timeout` 包住每次 ssh，長時間工作一律在 Spark 上 `setsid nohup … &` 啟動
- `run_jobs.sh`：單獨重跑指定段或其他工作，格式 `名稱 prompt檔 seed 秒數 首幀|-`
- 每段完成後抽幾格檢查（接縫、文字、角色外觀）

### 7. 配樂（H3）
- Spark 沒有音樂模型，用 H3 生成「無人物的靜態畫面＋純配樂」，只取音軌
- **prompt 一定要用官方格式**（見下方「H3 prompt 格式」）：`[Shot 1]` 寫空景、`overall_soundscape` 只寫風聲鳥鳴、`non_diegetic_music` 寫樂器、節奏、力度。範例 `density/prompts/music_official.txt`
  - 《密度》先用中文自由格式（結尾「純音樂，無對白、無人聲」）跑 seed 1、2，兩首都混進說話聲；改官方格式後同一個 seed 1 就乾淨。《蝴蝶》當時 3 首也有 1 首混人聲，原因相同
- 跑 1 首、ASR 檢查（轉不出文字，只回 `<|7.55|>` 之類的時間戳＝乾淨）→ 給使用者聽；有人聲再換 seed。選定的存成 `music/bgm.wav`

### 8. 合成 → `python3 mux.py <篇目>`
- H3 原生音軌**不直接用**（它會照 `<d>` 唸台詞、自己編說話聲）
- **實驗音效（《聲音》起）**：TTS 做不出鼓聲、敲桌、撥橡皮筋。H3 原生音軌裡的音效是和畫面一起生成的，時間點本來就對齊，所以用 Demucs 去掉人聲後保留：
  1. H3 全部跑完後，Spark 上 `bash sfx.sh <篇目> [段...]`：照 `shots` 抽原生音軌 → `demucs-sfx` 映像檔跑 `sfx_sep.py` → `sfx/SXX_novocals.wav`；已有的段跳過，H3 在跑時會拒絕啟動。12 段約 1 分鐘
     - 映像檔只要建一次：`docker build -t demucs-sfx -f Dockerfile.sfx .`（約 20 GB，含 htdemucs 權重）
     - 最後列出每段音效響度，低於 −45 LUFS 標「可能沒生成音效」。《聲音》被標的 7 段都是對話／旁白段，本來就沒有實驗音效；實驗段（敲鼓 −11.5、敲桌 −22、橡皮筋 −36）都有
     - Demucs 分離有隨機位移，重跑結果不會逐位元相同，響度一樣
  2. `mux.py` 偵測到 `sfx/SXX_novocals.wav` 就用它當底（`SFX_VOLUME` 0.6），沒有就照舊靜音
  - 先挑幾段疊回影片給使用者試聽再全片套用；《聲音》使用者直接試聽，沒跑 ASR
  - Demucs 裝法的坑：pip 不加 `--no-deps` 會重抓幾 GB 的 torch；4.1 版要 `sphn`，ARM 沒有 wheel；4.0.1 要 torchaudio，容器沒有 → 自己寫腳本呼叫 `apply_model`，給 openunmix 一個空的 torchaudio 模組
- 每句台詞先量響度、統一到 −20 LUFS（`LINE_LUFS`）再混音，避免某個角色偏小聲
- 台詞放在分鏡起秒；前句沒講完就順延，講不完用 atempo 加速（一般上限 1.35，段尾最後一句上限 1.5）
- 時段太緊的句子，優先在 `lines.json` 把起秒提前到沒有人說話的空檔，而不是硬加速
- 配樂以 1.5 秒交叉淡化循環到片長，音量 0.22，頭淡入 1 秒、尾淡出 3 秒

### 9. 字幕 → `python3 subs.py <篇目>`
- 依合成時實際排定的時間產生繁體中文 SRT；角色台詞標名字，旁白不標
- 片尾標語放畫面上方（`{\an8}`）
- 字型 Noto Sans CJK TC；壓字幕版另存 `butterfly_sub.mp4`，原版保留

## H3 prompt 格式（官方，2026-10-29 查證）

來源：專案內的官方 Colab notebook（`assets/MiniMax_H3_Turbo_Colab.ipynb`）與 MiniMax 官方〈[Video Prompt Writing Guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)〉。Studio 前端（`scripts/runner.py`）一直照這個格式寫，所以不會出現胡言亂語。

```
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.   ← 有首幀時才加（t2va 沒有）

integrated_multimodal_description: [Shot 1] …畫面、動作、說話者、台詞…
[Shot 2] At 00:04.000, the camera cuts to …

overall_soundscape: 1–4 句英文，環境音、動作聲、非語言人聲；不寫台詞

non_diegetic_music: 1–3 句英文，樂器、速度、節奏、力度；不寫抽象情緒；沒有配樂填 N/A
```

- 英文書寫；台詞保留原文放在 `<d>[Chinese] …</d>`，說話者編號 `(S1)` 寫在標籤外
- 只有 H3 要英文：Qwen-Image 首幀／尾幀 prompt 用中文就很準（《蝴蝶》《密度》全部中文），出錯多半是描述不夠具體（例：「浮在水面」要寫成「一半露出水面」），不是語言問題
- **只有 `<d>` 裡的內容會被唸出來**；不說話的角色不給說話者編號。官方沒有「無人聲」的寫法，寫了也沒用
- 旁白：`says in an off-screen voiceover`，並寫明畫面角色嘴巴閉著
- 台詞跨切鏡用 `<scenetrans>`，影片結束時話沒講完用 `<cutoff>`
- 《蝴蝶》全片、《密度》第一批都用中文自由格式，是 H3 編出非中文說話聲、配樂混人聲的主因
- **`expand.py` 已改為輸出官方格式**（config `prompt_format: official`，《蝴蝶》保留 `legacy`）：
  - LLM（8002）只回 JSON：`intro`、每列一句英文畫面描述 `ranges`、`final_frame`、`soundscape`；時間戳 `At 00:0X.000,`、`<d>[Chinese] 台詞</d>`、旁白 `A narrator says in an off-screen voiceover, … The on-screen characters' lips remain closed.`、首幀開頭句都由程式組，避免 LLM 抄錯
  - 8002 偶爾回不合法的 JSON（《彩虹》S05、S06），舊版 `expand.py` 會整批中斷、後面的段落留著舊檔：已改用 llama.cpp `response_format: json_object` 限制輸出，失敗自動重試 3 次。批次跑完要看 `prompts/` 的修改時間，確定每段都更新了
  - 讓 8002 直接寫整段官方格式時，會把中文風格句、`小明＝…` 定義原樣貼進去、把規則文字照抄、多加時間戳，所以改成程式組裝
  - 角色一律用 config 的英文名（`names_en`，如 Xiao Ming），說話者標籤也用同一個名字；中英混用 H3 可能對不上誰在說話
  - config 需要 `style_en`、`characters_en`、`names_en`、`no_text_rule_en`
- 驗證（《密度》S06，2026-10-29）：H3 原聲把三句台詞**一字不差唸成中文**（ASR 逐字相符），小明說話時張嘴、旁白時段閉嘴。合成時仍靜音原聲換 TTS，嘴型跟著真正的台詞時段走

## 這次踩到的坑

| 問題 | 原因 | 解法 |
|---|---|---|
| 影片裡有聽不懂的說話聲、配樂混人聲 | prompt 不是官方格式（中文自由段落），H3 自己猜音軌 | 合成時靜音原生音軌；配樂、影片段落都改官方格式後解決 |
| 結尾畫面出現亂碼字 | prompt 要求畫循環圖示，H3 自己加字 | 拿掉圖示，Qwen-Image 重做無文字首幀後重跑 |
| 小男孩聲音不像小孩 | 自動選的音色描述不準 | 改成候選人工挑選 |
| 4 句旁白混進日文／怪音（S04_09、S05_00、S09_00、S09_08） | reference 克隆在短句、並列詞上不穩 | 改 prompt 模式克隆＋ASR 篩選；把「長大後」改成「長大以後」也較穩 |
| ASR 核對漏掉一句壞句 | 只看錯字，沒注意漏字 | 漏字一律當壞句 |
| 繁體「湯匙」唸成怪音（《密度》） | VoxCPM2 對繁體字不熟 | 送 TTS 前一律 OpenCC 轉簡體 |
| 「變乾」唸成 qián | 多音字判斷錯誤，TTS 無拼音標註 | 送 TTS 時以同音字「甘」替換 |
| 看圖擴寫加入多餘角色 | 8002 照圖把角色塞進特寫 | 擴寫後程式檢查角色名稱，人工刪除 |
| 物體先浮後沉（《密度》S08 軟木塞、積木） | 首幀裡浮物畫成懸在水中，H3 照物理讓它沉 | 加尾幀鎖住結果，尾幀 prompt 寫「一半露出水面」 |
| 特寫拉遠後角色變大、髮色改變（《密度》S10） | 續接特寫末幀裡沒有角色，H3 自己畫 | 首尾幀：前段末幀＋Qwen 尾幀（中景含角色） |
| 角色中途入鏡後外觀走樣（《彩虹》S02 小美變黑髮） | 首幀沒有角色，8 秒後才入鏡，H3 自己畫 | 首幀沒有、後面才入鏡的角色，一律加 Qwen 尾幀（同《密度》S10）；角色參考用只裁出該角色的圖 |
| 續接段場景變成室內（《彩虹》S07） | 切塊的第 5 格右半部背景是室內牆面，8002 照圖寫成 "sunlit room"；分鏡沒寫場景 | 續接段每列也要寫場景；切塊後看背景是否和分鏡場景一致 |
| 太陽畫在彩虹前方（《彩虹》S05） | prompt 沒寫太陽位置，H3 自己加太陽 | 光學題材的 prompt 寫明光源位置（太陽在背後、不出現在前方天空）；第一次只加這句仍失敗，因為分鏡 8–12 秒寫「抬手遮陽」，H3 為了遮陽在前方畫太陽 → 動作也不能暗示光源方向 |
| 每段都出現木桌（《彩虹》S03、S05、S09） | 場景道具寫進 config 的 `style_en`，變成全片共用 | 風格欄只寫畫風；場景寫在各段分鏡 |
| 照整格原圖加進多餘角色（《彩虹》S09） | 兩段共用一格，8002 看到整格 | 原圖依段切塊，分鏡寫明「畫面只有某某」 |
| 林博士聲音小聲聽不清楚 | 各角色 TTS 響度差到 14 dB（林博士 −28.6 LUFS） | mux.py 每句統一 −20 LUFS |
| 獨立段畫風不一致（部分偏 3D） | t2va 段落沒有共用參考 | 尚未解決：可改為每段都用 Qwen-Image 首幀 |

## 尾幀（官方說明，2026-10-29 查證）

H3 官方支援三種圖片錨定：首幀（I2VA）、尾幀（L2VA）、首尾幀（FL2VA，兩張圖）。
- 尾幀寫法：`<Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.`（S.SS＝片長，取兩位小數）
- 首尾幀：Picture 1 用首幀句，Picture 2 用上面的尾幀句；官方建議單一 [Shot]，讓模型連續內插。
- 不支援片中任意秒數的關鍵幀。
- 用途：續接段的「特寫拉遠」要角色入鏡時，可用「前段末幀＋Qwen 尾幀」鎖住角色外觀；物理結果（浮/沉）也能用尾幀鎖定。
- 實作：放 `<篇目>/frames/SXX_end.png`、config `last_frames` 列入該段 → expand.py 加尾幀句、run_series.sh 傳 `H3_LAST_FRAME`（Spark bench.py 接到 MiniMaxH3ImageToVideo 的 last_frame）。
- 尾幀用 Qwen-Image 做，參考圖放該段首幀（或前段末幀＋角色圖）；浮在水面的物體要寫「一半露出水面」，否則 Qwen 會畫成懸在水中，H3 就會讓它沉下去（密度 S08）。
